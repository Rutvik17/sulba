# 11. Build the interface on tokens, CSS and React Aria Components

- Status: accepted
- Date: 2026-10-09

## Context

Phase 1 builds the design system every course shares. The look is the prototype's: monochrome grounds, hairline frames, one accent, light and dark themes. Interactive parts need menus, dialogs, tabs, sliders and form fields that work with a keyboard and a screen reader, because every page must pass WCAG 2.2 AA, which axe checks in CI. Pages without an interactive part send no JavaScript (record 2), fonts must come from Sulba's own domain, and one person builds the site, so the hard accessibility problems should be solved by a maintained library.

## Decision

- Colour, type, spacing, radius and motion are CSS custom properties in `packages/ui`, each colour with a light and a dark value. With no saved choice the site follows the device's setting; a saved choice is applied before the first paint. Components read tokens and write no colour of their own, and a unit test checks every text colour against WCAG contrast on every ground.
- Styles are plain CSS. The tokens, a reset and the base styles sit in cascade layers, beneath component styles: scoped `<style>` blocks in Astro components and CSS Modules in React components. No CSS-in-JS at run time and no utility framework.
- Native elements come first: where HTML already provides a control (a link, a button, a radio group, a form field, a popover), the page uses it and needs no framework. Widgets HTML lacks, such as tabs, sliders, comboboxes and dialogs that trap focus, take their behaviour from React Aria Components and their look from Sulba's CSS, through the state attributes it sets.
- Geist, Geist Mono and Instrument Serif come from Fontsource packages through Astro's Fonts API, read from `node_modules` at build time and served from sulba.dev with fallback fonts Astro generates.

## Options

Behaviour of interactive components:

| | React Aria Components | Base UI | Radix Primitives | Written by hand |
| --- | --- | --- | --- | --- |
| Accessibility | W3C semantics and keyboard behaviour; "extensively tested using many popular screen readers and devices"; overlays contain and restore focus | WAI-ARIA design patterns, tested across platforms, browsers and screen readers | WAI-ARIA design patterns "where possible" | Tested by Sulba, widget by widget |
| Languages | Translations in over 30 languages, right-to-left layout | Not described on its about page | Not described on its introduction page | Sulba's to write |
| Styling | Unstyled; states as data attributes | Unstyled; no bundled CSS | Unstyled | Sulba's |
| Maintained by | Adobe | The creators of Radix, Material UI and Floating UI; version 1.9.0 | Its introduction page says nothing about maintenance | Sulba |

| | CSS Modules in cascade layers | Tailwind CSS 4 | vanilla-extract |
| --- | --- | --- | --- |

| Cost at run time | None | None | None, static CSS generated at build time |
| Tokens | Custom properties | Theme variables, also emitted as custom properties | Typed theme contracts |
| Tooling | Built into Vite, which Astro uses | Its own compiler | A Vite integration |

## Evidence

- React Aria Components: [overview](https://react-aria.adobe.com/) and [getting started](https://react-aria.adobe.com/getting-started).
- [Base UI, about](https://base-ui.com/react/overview/about) and [Radix Primitives, introduction](https://www.radix-ui.com/primitives/docs/overview/introduction).
- [Tailwind CSS theme variables](https://tailwindcss.com/docs/theme), [vanilla-extract](https://vanilla-extract.style/) and [CSS Modules in Vite](https://vite.dev/guide/features#css-modules).
- [Cascade layers on MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer): widely available across browsers since March 2022.
- Astro's [Fonts guide](https://docs.astro.build/en/guides/fonts/) and [font provider reference](https://docs.astro.build/en/reference/font-provider-reference/): the npm provider reads `@fontsource` packages from `node_modules`, and with `remote: false` it never falls back to a CDN.
- [WCAG 2.2, Understanding 1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html): 4.5:1 for text, 3:1 for text of at least 24px, or 18.5px bold.

## Why

Accessibility is where a design system usually fails, and React Aria publishes the broadest testing of the three libraries: screen readers, devices, focus management and translated messages. Plain CSS keeps the prototype's styles as they are written and costs nothing at run time, and layers let any component style override the base styles without a fight over selector specificity. Serving fonts from sulba.dev keeps every request on Sulba's own domain, and the lockfile pins what is served.

The strongest case against: Base UI covers the same widgets and comes from the team that built Radix, which more React developers know. React Aria trades that familiarity for its wider testing and its internationalisation.

## Consequences

A page with an interactive part loads React and the React Aria components it uses; a page without one loads no JavaScript. Every component's CSS is written by hand, and colours live only in the tokens.

## Revisit when

React Aria's releases slow, another library documents equal screen-reader testing, or Astro's Fonts API changes how it resolves packages.
