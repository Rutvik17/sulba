OpenTelemetry's semantic conventions for generative AI, at release 1.41.1 and still marked Development, name a chat request's span `{gen_ai.operation.name} {gen_ai.request.model}`, a tool's `execute_tool {gen_ai.tool.name}` and an agent's `invoke_agent {gen_ai.agent.name}`. A chat request goes over HTTP to another process, the model's server, and for those the conventions recommend the kind `CLIENT`; a tool's span and an agent's that runs in the same process are `INTERNAL`. llama.cpp isn't among the providers the conventions list, and for a provider they don't list, "a custom value MAY be used".

Errors follow the conventions' document on recording them. A span's status "MUST be left unset if the instrumented operation has ended without any errors", and when the operation ends with one, instrumentation "SHOULD set the span status code to `Error`" and "SHOULD set the `error.type` attribute". `error.type` "SHOULD be predictable, and SHOULD have low cardinality": a status code or an exception's class, so that errors can be counted by kind, with the exception's message in the status's description.

Each run's spans share its trace: the agent's span at the root, and beneath it every request, every tool and every sub-agent the run called. A run's row comes from its trace alone, so the scores and percentiles of the last two stages can be worked out from an agent's runs in production, not only from a test set run on purpose.
