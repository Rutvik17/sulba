The caller's yes is checked in code, and the model never reaches a write. OWASP's Top 10 for LLM Applications counts an application that "fails to independently verify and approve high-impact actions" as one with excessive autonomy, and among its mitigations is to "require a human to approve high-impact actions before they are taken". A rule in a prompt is a request the model can miss; a write that only `confirm` makes can't happen before the yes, whatever the model does.

A proposal looks up what it needs before the caller is asked. Anthropic's guide to writing tools suggests "a schedule_event tool which finds availability and schedules an event" in place of separate tools to list users, list events and create one. `propose_callback` is the desk's: the model names the service, the day and the part of the day as the caller said them, and the desk finds the ticket and the time. The caller is asked about a call the desk can make, and a call it can't make is an error the model reads before it says anything, with what to ask the caller instead.

A yes is checked again. Between the proposal and the yes, another booking can take the time. `confirm` checks the time before it writes anything, so it opens no ticket for a call it can't book, and the caller hears why.
