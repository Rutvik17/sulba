A tool's result is a prompt the model reads in the middle of its work. Anthropic's guide to writing tools for agents says their implementations "should take care to return only high signal information back to agents", and that resolving opaque identifiers to meaningful ones "significantly improves Claude's precision in retrieval tasks by reducing hallucinations". The desk's search shows each passage the way the reply should cite it, `[p17]`, beside the instruction to cite, so the citation is already in the model's context in the form it has to write.

A list says what it leaves out. `list_tickets` shows the open tickets, which callbacks are booked on, and says how many closed ones there are and how to see them, so the model knows the list isn't the whole account, and how to see the rest.

An error is a result too. A model that called a tool wrongly calls again from what the error says, so each error names what was wrong and what would work: the tools there are, the values a field takes, or a call that fits. The same guide recommends prompt-engineering error responses "to clearly communicate specific and actionable improvements, rather than opaque error codes or tracebacks". The spec does most of the checking: `enum` lists every value a field can take, as OpenAI's function-calling guide advises, "Use enums and object structure to prevent invalid states", and `run` holds each call to it before any tool runs, so a tool only ever sees arguments that fit.

The model calls no tool that writes. `open_ticket`, `book_callback` and `cancel_callback` are the desk's own, for the next stage to call once the caller has said yes.
