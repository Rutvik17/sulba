The tools are how a model acts on the desk, and what it reads back is all it knows of what happened. A tool that raises leaves the program to decide what the caller hears; a tool that gives `{"error": "The ssa advisers aren't free on 2026-11-02 at 09:00."}` lets the model read it and do something about it, such as ask for the free times and offer one. Anthropic's account of its research agents puts it this way: "letting the agent know when a tool is failing and letting it adapt works surprisingly well."

`call` checks a call against the tool's own description before it runs it, so a model's mistake, a missing argument, one the tool doesn't take, JSON cut off in the middle, comes back as an error too, and never reaches the code as an exception. Each tool gives copies of the desk's tickets and times, so nothing outside the desk can change them except through a tool.

`writes` keeps what the desk changed, and when. The desk's {% $fig.tasks %} tasks are graded on it: a ticket opened or a callback booked must come after the caller's yes, in their last message, and not before, and a vague request must leave it empty. Every write goes through the tools, so the desk's state at the end says what each way of running it did, whatever its replies said.
