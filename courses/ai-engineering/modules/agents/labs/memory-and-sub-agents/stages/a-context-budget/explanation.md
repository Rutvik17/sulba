Most of a request is tool results. Each search gives five passages, which the model reads for the question it searched for, and every later request sends them again. Anthropic's guide to context engineering calls clearing them "One of the safest lightest touch forms of compaction". A cleared result keeps its place, with the call that made it, so the model still sees what it searched for, and the conversation still pairs each call with its result.

The budget is checked against the last request's usage, which the server counts with the model's own tokenizer: the next request sends all of it again, and the new message. Counting before sending would mean tokenizing the conversation in the desk, with the tokenizer and chat template the server uses. The usage is exact and costs nothing, but it's one request late, so a budget sits well below the context, with room for one more message and a reply.
