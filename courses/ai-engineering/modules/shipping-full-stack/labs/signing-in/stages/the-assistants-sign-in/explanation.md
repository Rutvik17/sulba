Each problem passed the assistant's tests because every test signed in one person, in a fresh browser, with an ordinary path back. No test gave a path to another site, set a cookie before signing in, signed in two people with the same email, or kept a token after signing out.

The four are the usual ways a sign-in goes wrong once it's live. An open redirect: OWASP's cheat sheet on redirects says "If used, do not allow the URL as user input for the destination", and for a return path, use "a framework helper that rejects non-local destinations". A browser reads `//` at the start of a path as the start of another site's address. The URL Standard, which browsers follow, also reads a backslash in an `https:` address as a slash, and says to "Remove all ASCII tab or newline from input" before reading it. Starlette writes a tab or a backslash into the `Location` header percent-encoded, as `%09` or `%5C`, so neither reaches the browser as itself, but the rule holds whatever writes the header.

Session fixation: OWASP's Session Management Cheat Sheet says "The session ID must be renewed or regenerated by the web application after any privilege level change within the associated user session. The most common scenario where the session ID regeneration is mandatory is during the authentication process". An account found by email, where OpenID Connect promises only the issuer and subject are stable. And a sign-out that forgets the server, where the same sheet says of a session's end: "When a session expires, the web application must take active actions to invalidate the session on both sides, client and server. The latter is the most relevant and mandatory from a security perspective."
