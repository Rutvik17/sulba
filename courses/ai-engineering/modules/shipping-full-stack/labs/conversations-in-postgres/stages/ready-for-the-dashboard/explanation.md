The database's address has no default. The app can't run without a database, and a default address would point every copy of the app at whatever database happened to answer there. Each copy migrates as it starts, and the advisory lock lets several copies start at once.

A day is a day in UTC. Postgres's documentation says "All timezone-aware dates and times are stored internally in UTC. They are converted to local time in the zone specified by the TimeZone configuration parameter before being displayed to the client." A turn's day, taken from `started_at` alone, moves with the time zone of whoever asks, and a database, a role or a connection can each set its own. `AT TIME ZONE 'UTC'` gives the time "as the time would appear in that zone", whatever the session's setting.

`percentile_cont` "Computes the continuous percentile, a value corresponding to the specified fraction within the ordered set of aggregated argument values. This will interpolate between adjacent input items if needed."

The week's turns are found through the index. An index on `started_at` can find the turns whose `started_at` is in a range. It can't find the ones whose day, worked out from `started_at`, is: Postgres's documentation on indexes on expressions shows that such a query "can use an index if one has been defined on the result" of the expression. Comparing `started_at` itself with the first moment of the first day gives the index a range to find. `EXPLAIN` shows which the planner chose: "You can use the EXPLAIN command to see what query plan the planner creates for any query."
