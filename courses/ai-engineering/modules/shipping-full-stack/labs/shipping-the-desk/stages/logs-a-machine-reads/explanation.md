A JSON line is one record a host can filter on any field: every line of one request, every `ERROR`, every request that took over a second. Python's own formatter writes the machine's local time, as its documentation says of `formatTime`: "By default, time.localtime() is used". Each line here is in UTC, so lines from machines in different zones sort together. A traceback inside the line's JSON keeps the record on one line, for a host that reads a line at a time.

The request's id is a context variable. Python's documentation: "Context managers that have state should use Context Variables instead of threading.local() to prevent their state from bleeding to other code unexpectedly, when used in concurrent code." Each request runs in a task of its own, and "If no context is provided, the Task copies the current context and later runs its coroutine in the copied context", so a line written for one request never carries another's id. An id from outside goes into every line, so only a short, plain one is kept. OWASP's Logging Cheat Sheet asks you to "Perform sanitization on all event data to prevent log injection attacks e.g. carriage return (CR), line feed (LF) and delimiter characters". A proxy in front of the desk that sends its own id finds the desk's lines for its request by it, and a caller with a problem can quote the id the answer carried.

Some things never belong in a log. OWASP lists what "should usually not be recorded directly in the logs, but instead should be removed, masked, sanitized, hashed, or encrypted", among them "Access tokens", "Authentication passwords", "Database connection strings" and "Encryption keys and other primary secrets". A request's headers carry the desk's session cookie, and its settings carry the provider's client secret and the database's address with its password, so a field named for one is hidden wherever it sits. The request's line keeps the path without its query, which can hold a sign-in code or a person's details.
