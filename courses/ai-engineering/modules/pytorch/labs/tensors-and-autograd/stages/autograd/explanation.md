Autograd keeps a graph as the forward pass runs. Each tensor an operation makes from a tensor that requires gradients holds `grad_fn`, the operation's backward pass, linked to its inputs' own. The loss's `grad_fn` reaches back through the output layer, the ReLU and the hidden layer to the weights and biases, the graph's leaves. `backward()` walks the graph in reverse, as your engine's backward pass did in topological order, and adds each leaf's gradient to its `.grad`.

Adding is deliberate. A parameter used twice collects both gradients, and a batch too large to fit at once can be split into smaller ones whose gradients add up. It also means a gradient stays until something clears it, so a training loop clears `.grad` before or after each step, with `param.grad = None` or an optimizer's `zero_grad()`. `torch.autograd.grad` returns the gradients and adds them nowhere.

The step itself changes the parameters, and autograd would record that as one more operation, so it runs inside `torch.no_grad()`. Made in place, with `-=`, it changes each parameter itself, which stays the same leaf tensor. `param = param - lr * param.grad` would make a new tensor, one that under `torch.no_grad()` doesn't require gradients, and leave the parameter in the dict as it was.
