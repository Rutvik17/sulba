A checkpoint is a pickle, and loading a pickle runs whatever code it names, so a checkpoint from the web runs on the machine that loads it. With `weights_only=True`, `torch.load` rebuilds only tensors and plain containers, and refuses the rest. `map_location="cpu"` loads weights saved from a GPU on a machine without one.

`strict=True` refuses a checkpoint whose names don't match the model's. Without it, a parameter the checkpoint lacks would keep the random values it was made with, and the backbone would give poor features with no error. This checkpoint holds {% $fig.weights %} tensors, {% $fig.parameters %} numbers between them, in `float32` at 4 bytes each: {% $fig.float_mb %} of the file's {% $fig.file_mb %}. Frozen, the backbone needs no gradients, and `torch.no_grad()` keeps no graph for a backward pass, so features take one pass forward and the memory of one batch at a time. `torch.inference_mode()` would keep no graph either, but its tensors can't be saved for a backward pass, so a layer couldn't learn from features it gave. Eval mode turns off what layers do only in training, such as dropout, which this port leaves out.

The backbone learned from images normalized with ImageNet's mean and standard deviation, so its layers expect inputs on that scale, and tiles on another give other features. Its position embeddings are for images of {% $fig.trained %} by {% $fig.trained %} pixels, {% $fig.grid %} by {% $fig.grid %} patches, and `positions` resizes them to the patches of another size. A side must be a multiple of {% $fig.patch %} for the patches to cover the image. At {% $fig.side %} pixels, a tile is {% $fig.patches %} patches and a class token: {% $fig.tokens %} tokens. Most of the work grows with the tokens, and attention's with their square: a tile takes {% $fig.macs_side %} multiply-adds at {% $fig.side %} pixels a side, and {% $fig.macs_large %} at {% $fig.large %}.
