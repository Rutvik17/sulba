The backbone's features already set the kinds apart, so a linear layer on them is enough: {% $fig.parameters %} weights and biases, {% $fig.width %} weights and a bias for each kind, learned from {% $fig.labelled_total %} tiles. With {% $fig.labelled %} labelled tiles of each kind, the probe is right on {% $fig.accuracy %} of {% $fig.tested %} test tiles, {% $fig.per_test %} of each kind, and with {% $fig.fewer %} of each, on {% $fig.fewer_accuracy %}. A small convolutional network trained from nothing on the same {% $fig.labelled_total %} tiles for {% $fig.epochs %} epochs, each tile flipped at random as it learns, is right on fewer than {% $fig.bound %} of them, since it has to learn its features from those tiles too.

Standardized, every feature has a mean of 0 and a standard deviation of 1 over the labelled tiles, so the decay weighs each feature's weights alike, and L-BFGS takes steps that suit every feature. The mean and deviation come from the labelled tiles alone and stay in the probe, so a new tile is standardized as they were, and its scores don't depend on the tiles scored with it.

{% $fig.labelled_total %} points in {% $fig.width %} dimensions can always be split by kind with planes, so without the decay the loss would fall toward 0 as the weights grew without end, and L-BFGS would stop wherever its steps ran out. With it, the loss has one lowest point, which L-BFGS finds closely in `float64`, on any machine.

An accuracy measured on {% $fig.tested %} tiles is a sample: its standard error is {% $fig.error %}, so on another {% $fig.tested %} tiles like them the probe's share would usually come within about twice that, {% $fig.twice %}, of {% $fig.accuracy %}. The confusion shows where it goes wrong: it takes {% $fig.confused_count %} of the {% $fig.per_test %} {% $fig.confused %} tiles for {% $fig.confused_as %}, the pair it mixes up most.
