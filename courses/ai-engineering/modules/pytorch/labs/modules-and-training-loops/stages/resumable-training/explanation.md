The run validated best after epoch {% $fig.best %}, with a loss of {% $fig.best_loss %} on the {% $fig.validation %} validation digits, and that epoch's reader reads {% $fig.best_right %} of the test digits. The last epoch's, at {% $fig.last_loss %}, reads more of them, {% $fig.last_right %}, but the choice is made on the validation digits, and the test digits only judge it afterwards. Chosen on the test digits, the reader would have nothing left to judge it.

Keeping the best epoch takes a copy. `state_dict()` holds the reader's own tensors, which every later step changes, so by the end of the run a dict kept from it holds the last epoch's weights. `copy.deepcopy` copies them. The best so far is part of the run's state too: a run stopped after the best epoch that forgot it would return whichever later epoch validated best. So the checkpoint holds it beside the reader, the optimizer, the generator and the count.

A stop while saving is the one stop a checkpoint can't survive by itself: `torch.save` writing over the last checkpoint leaves neither it nor the new one whole. Written first to a file beside it, then moved over it with `os.replace`, the new checkpoint replaces the old one only once it's complete, so a stop while writing leaves the last checkpoint as it was.
