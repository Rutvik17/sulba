A struct tag is how JSON's names meet Go's. Go exports only the names that start with a capital, so `ChatRequest`'s fields are `Model` and `MaxTokens`, and json's docs say how it matches them: it "matches incoming object keys to the keys used by Marshal (either the struct field name or its tag), preferring an exact match but also accepting a case-insensitive match." So `model` would find `Model` without a tag, but `max_tokens` never finds `MaxTokens`, and the docs go on: "object keys which don't have a corresponding struct field are ignored". Without the tag, a request's `max_tokens` would vanish, and every request would get the limit.

In Go, a failure is a value. A function that can fail returns an `error` as its last result, and its caller checks it. An error such as `ErrNoModel` is a value made once with `errors.New`, which callers compare with, and `*FieldError` is a type of error, which carries the field and the problem. The `errors` package says how to find each: `errors.Is(err, fs.ErrExist)` "is preferable to `err == fs.ErrExist` because the former will succeed if err wraps io/fs.ErrExist", and `errors.AsType[*fs.PathError](err)` is preferable to a type assertion "because the former will succeed if err wraps an *io/fs.PathError." The gateway's server will wrap these errors as it passes them up, so its callers use `Is` and `AsType` from the start.

`fmt.Errorf` with `%w` wraps an error, and with two `%w`s it wraps both. A caller can then ask for `ErrNotJSON`, to answer 400, or for json's `*SyntaxError`, for where the JSON broke. Wrapping is a promise, as Go's blog on errors puts it: "wrapping an error makes that error part of your API." `DecodeRequest` wraps json's error on purpose, and turns its `*UnmarshalTypeError` into the gateway's own `*FieldError`, so a caller sees one type for every field that's wrong.

`Decode` reads one value and stops, so a body with a second object after the first would pass unread. `decoder.More()` "reports whether there is another element in the current array or object being parsed", and after the top-level value it reports whether anything is left.

`FieldError`'s `Error` method has a pointer receiver, so it's `*FieldError` that is an `error`, and the code returns `&FieldError{...}`. That's the type a caller asks `AsType` for.
