With batch normalization there instead, Kaiming's start read {% $fig.batch_kaiming %}, and `nn.Linear`'s, the starter's, {% $fig.batch_default %}. The solution takes the better, and reads {% $fig.chosen_test %} of the test digits. Kaiming's start keeps the signal's size at the first step, and batch normalization keeps it at every step.

Batch normalization takes the weights' scale out of the outputs: it divides each feature by its spread over the batch, so weights `$a$` times as large give the same outputs, `$\epsilon$` aside. What the scale still changes is the steps. Weights `$a$` times as large get `$1/a$` of the gradient, so for their size they move `$1/a^2$` as far. Kaiming's range is {% $fig.ratio %} times `nn.Linear`'s, so with batch normalization after it, `nn.Linear`'s start takes steps {% $fig.factor %} times as large for its weights' size.

A linear layer's bias does nothing before batch normalization, which subtracts each feature's mean over the batch, and the bias with it: the bias's gradient is 0, and `$\beta$` shifts each feature instead. The solution starts those biases at 0, as `torch.nn.Linear` with `bias=False` leaves them out.
