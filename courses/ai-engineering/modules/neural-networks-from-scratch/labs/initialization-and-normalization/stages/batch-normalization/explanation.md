The backward pass has three terms because each `$x$` reaches the loss three ways: through its own `$\hat{x}$`, through the batch's mean, which every `$\hat{x}$` subtracts, and through the batch's variance, which every `$\hat{x}$` divides by. The two sums are those shared paths. They make the gradient of each feature sum to 0 over the batch, and be at right angles to `$\hat{x}$`: a shift or a stretch of the whole batch changes nothing after normalization, so the gradient has no part along either.

The variance is biased in training because that's the one the batch is normalized with, and unbiased in the estimate because the estimate stands for the variance of the inputs evaluation will see, of which a batch is a sample. The two differ by a factor of `$n / (n - 1)$`: {% $fig.small_factor %} in the recorded batches of {% $fig.small %}, and {% $fig.large_factor %} in those of {% $fig.large %}.

The momentum here is not an optimizer's: it's the weight each new batch gets in the running estimate, {% $fig.momentum %}, so each estimate keeps {% $fig.kept %} of itself at every batch. PyTorch's documentation warns of the difference. Evaluation never changes the estimates, so a network reads a digit the same way whatever else is in its batch.
