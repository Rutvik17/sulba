Momentum keeps a running sum of the gradients, each weighted by `$\mu$` once for every step since it came. Along a direction where the gradient stays the same, the buffer grows toward `$g / (1 - \mu)$`, {% $fig.limit %} times the gradient for `$\mu$` = {% $fig.mu %}, so the steps there grow up to {% $fig.limit %} times as long. Across a narrow valley, where the gradient changes sign from one step to the next, the terms cancel, and the steps shrink.

PyTorch keeps the velocity in the gradient's units and multiplies the whole of it by the learning rate at each step, so a new learning rate takes effect at once. Its documentation notes that this differs from another common form, `$v \leftarrow \mu v + \gamma g$` and `$\theta \leftarrow \theta - v$`, in which the velocity carries the learning rates it was built with. The two take the same steps while the learning rate stays the same. PyTorch also starts the buffer at the first gradient rather than at 0, so dampening starts at the second step.

Updating in place is what lets an optimizer work for any network. The network keeps its own arrays, the backward pass fills in the gradients, and the optimizer changes the arrays themselves, so nothing has to be handed back.
