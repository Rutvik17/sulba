On the office's network, with {% $fig.batches %} batches of {% $fig.batch %} training digits and learning rates rising from {% $fig.lr_min %} to {% $fig.lr_max %}, the smoothed loss was lowest at a learning rate of {% $fig.lowest %}. That's where the steps start to be too large: trained for {% $fig.steps %} steps at that learning rate, the network read fewer than {% $fig.target %} of the validation digits. At half of it, it read {% $fig.half %}, at a third {% $fig.third %}, and at a tenth {% $fig.tenth %}. A learning rate a few times below the lowest point trains well, and one far below it trains slowly.

The smoothing has a cost. An average that keeps `$\beta$` = {% $fig.beta %} of itself remembers about `$1 / (1 - \beta)$`, {% $fig.memory %}, steps, so its curve trails the loss it smooths. A smaller `$\beta$` follows the loss more closely, and smooths it less.
