The failures worth retrying are the ones that say nothing about the request. A `408` says the server stopped waiting for the request, a `409` that it met a conflict on the server's side, a `429` that the client sent too many, and a `5xx` that the server failed: each may pass. The openai package, version {% $fig.openai %}, asks again after the same statuses, {% $fig.retries %} times by default. A `400`, `401`, `403` or `404` is about the request, the key or the path, and asking again only adds to the bill.

`Retry-After` is the server saying when to come back. HTTP's specifications let it be a number of seconds or a date, on a `429` or a `503` among others, so a client that reads it waits no longer than it must and no less than it was asked. Without it, the wait doubles, so a server that is struggling gets fewer requests the longer it struggles. The random factor spreads out clients that failed together, as when a server restarts: without it, they'd all ask again at the same moments. The openai package waits {% $fig.openai_first %} seconds at first, doubling up to {% $fig.openai_most %}, and takes up to a quarter off each wait at random.

A timeout and a deadline answer different questions. The timeout says how long one attempt may take, so a reply that never comes costs one attempt, not the whole deadline. The deadline says how long the customer waits, so the last attempt gets only the time that's left, and a wait that would outlast it isn't started. Giving up then lets the assistant tell the customer at once, rather than after a wait that can't end in an answer.

A timeout ends the client's wait, not the server's work, so a request that timed out may still have been answered, and billed. Asking a model again is safe because it changes nothing but the bill. A request that books a repair would need the server to recognize it the second time it came.
