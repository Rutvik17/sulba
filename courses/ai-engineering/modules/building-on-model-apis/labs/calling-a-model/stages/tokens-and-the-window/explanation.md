Every message pays for its markers, and every request pays again for the whole conversation. The lab's long conversation ends at {% $fig.long_tokens %} tokens, but its {% $fig.questions %} questions, each sent with the conversation before it, have the model read {% $fig.long_read %} in all. A conversation's tokens grow with each turn, and what it costs grows faster.

The template is the model's own: Qwen3.5 was trained on conversations written this way, and another model writes them its own way. The server writes the text itself, from the template in the model's file, so the client sends plain messages and never sees these tokens. Counting them takes the same template and tokenizer, which is why `prompt_tokens` in a reply is the only count a client gets for free.

`fit` drops whole turns because a reply without the question it answered misleads the model, and it keeps the system message because that holds the shop's instructions. It leaves room for the reply because the server's window holds the reply's tokens as well as the prompt's. When a prompt fills the window, llama.cpp's server answers with a `400`, and when a reply reaches its end, the reply stops with `length`. Qwen3.5-0.8B was trained to read {% $fig.trained %} tokens, but every token in the window takes memory, so the lab's server holds far fewer.
