Say the shop's assistant has {% $fig.conversations %} conversations a month, each of {% $fig.questions %} questions. Every request carries the shop's instructions, {% $fig.instructions %} tokens, then the conversation: a first question adds {% $fig.first %} tokens, and each later one {% $fig.later %} with the replies before it. Every reply takes {% $fig.reply %}. With every token read fresh, the month costs {% $fig.small_month %} on `gpt-6-luna` or `claude-haiku-5-5`, and {% $fig.large_month %} on `gpt-6.1-sol` or `claude-sonnet-5-5`, {% $fig.times %} times as much. The model is the largest choice in the bill, and whether a smaller one answers well enough is for the shop to measure on its own questions.

The instructions are the same in every request, which is what a provider's cache is for. If each conversation's first request writes them to the cache and the later ones read them from it, the month on `gpt-6-luna` costs {% $fig.cached_month %}. OpenAI's prompt caching guide says a cache write isn't an extra fee: each prompt token pays one of the three prices. But a client that reads OpenAI's `prompt_tokens` as fresh tokens, as Anthropic's `input_tokens` are, counts the cached and written tokens twice, and puts the same month at {% $fig.misread_month %}, more than with no cache at all.

A cache keeps a prompt's beginning only, and only for a while, so the shop's instructions go first and stay the same. Both providers say how long a cached prompt lasts and the shortest one they cache, and their rules differ from model to model, so a month priced in advance is an estimate. The usage each reply reports is what the bill is made of.
