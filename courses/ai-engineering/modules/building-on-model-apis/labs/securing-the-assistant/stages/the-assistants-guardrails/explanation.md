Each problem passed the assistant's tests because the tests' model did only what the customer asked. The checks' model did whatever it read: a customer's trick question, a review's instructions, a request for its own instructions. That's what a model does when a prompt injection works, and the code has to hold all the same.

`taken_times` needed the times, and returned whole bookings. A tool's result is something the model may repeat to anyone, so a tool sends only what its answer needs: against sensitive information disclosure, OWASP's Top 10 for LLM Applications gives least privilege, only the data a user or a process needs.

A tool that confirms is a tool the model can be talked into calling. The confirmation is the customer's alone, so it travels outside the conversation, from the button to `confirm`.

Instructions aren't secret: a model can be talked into repeating them, which OWASP's list calls system prompt leakage, so they hold nothing a customer mustn't see, from codes to credentials. What only some customers may have is given by code that knows who's signed in.

Each request's prompt carries the whole conversation and every tool result, again in every round, so it's usually most of what the request uses. Counting only the replies let a customer run on long after their day should have ended, which OWASP's list calls unbounded consumption.
