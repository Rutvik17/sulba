The API keeps nothing between requests, so every round sends the conversation again: the customer's question, each call the model made, in the message that made it, and each result after it, under the call's id. The id says which call a result answers. Qwen3.5's chat template shows the model its calls and their results without the ids, each result in the order it comes, so the results go back in the order of the calls too.

A reply can call several tools at once. OpenAI's guide says it plainly: "Since model responses can include zero, one, or multiple calls, it is best practice to assume there are several." The calls in one reply don't depend on each other's results, so they can run in any order, or at the same time, as long as the results go back in the order of the calls, each with its own id. `"parallel_tool_calls": false` asks for one call at most.

The rounds are capped because each one is another request to the model, which a customer waits on, and a model can call tools in a loop: the same tool again and again, or one that keeps failing. When the rounds are spent, `NoAnswer` lets the assistant tell the customer at once. `"tool_choice": "none"` on the last request is another way: it asks the model to answer with what it has.
