A tool's name, description and schema are all the model knows of it, so the docstring and each parameter's description are written for the model, as instructions are. A parameter whose values are few, such as a day of the week, is an `enum`, which names every value the model may pass.

With `strict`, OpenAI's API holds a call's arguments to the schema, which is why every object sets `"additionalProperties": false` and lists every property in `required`, a parameter that can be empty having `null` among its types. Without it, a call follows the schema only as best it can, and the API's reference warns that "the model does not always generate valid JSON, and may hallucinate parameters not defined by your function schema. Validate the arguments in your code before calling your function."

`run` checks that the arguments are JSON with exactly the function's parameters, and never raises. The model asked for the call, and the model can fix it: told that no function has the name it gave, or that its arguments missed a parameter, it can call again. An exception would end the conversation instead. The same holds for a function's own errors, which say, in the function's words, what the model got wrong.
