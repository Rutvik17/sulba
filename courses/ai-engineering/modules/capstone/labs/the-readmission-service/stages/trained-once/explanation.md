`python train.py` fits the model on all {% $fig.stays %} stays and writes `model.joblib`: the fitted pipeline, with its means and spreads, its categories and its {% $fig.weights %} weights, and the threshold, recall and precision `train` set. The service loads that file when it starts, so it answers with the model whose numbers the planners were given, and it starts without the extract or a fit.

A model saved with one version of scikit-learn may load in another, but scikit-learn doesn't support it, and its documentation warns that the results can differ or the process can crash. scikit-learn itself only warns, with an `InconsistentVersionWarning`, so `load` refuses the file instead, and the remedy is to train again with the versions running. Here they are scikit-learn {% $fig.sklearn %} and the NumPy and SciPy it runs with. The documentation also advises keeping a reference to the training data, the code that trained the model and its cross-validation score beside it, so a model trained again can be checked against the old one.

joblib saves with Python's pickle, and loading a pickle runs whatever code the file says to run. Load only files you made, as the service loads the one `train.py` wrote, and never one a request or an upload could supply.
