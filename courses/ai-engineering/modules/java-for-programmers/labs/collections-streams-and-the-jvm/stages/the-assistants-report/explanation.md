Each problem passed the assistant's tests because each test used the figures as the assistant pictured a quiet morning. No test had an old question anywhere but first of two, no page was asked about twice when its slowest reply was read, no page had more than two questions, and no test spanned two hours.

`prune` changed the list it was looping over. `ArrayList`'s iterators "are fail-fast: if the list is structurally modified at any time after the iterator is created, in any way except through the iterator's own remove or add methods, the iterator will throw a ConcurrentModificationException." The for-each loop is that iterator, and `log.remove(asked)` isn't the iterator's own remove. The assistant's test removed the first of two questions, which leaves one question and an iterator already past it, so the loop ended before its next check, and the docs warn against leaning on the exception either way: "it would be wrong to write a program that depended on this exception for its correctness". `removeIf` removes through the list itself. In Python, removing from a list while looping over it skips elements without a word, which is worse.

`Collectors.toMap(keyMapper, valueMapper)` is for keys that don't repeat: "If the mapped keys contain duplicates (according to Object.equals(Object)), an IllegalStateException is thrown when the collection operation is performed. If the mapped keys might have duplicates, use toMap(Function, Function, BinaryOperator) instead." The third argument says which of two values to keep, here the longer reply. A Python dict comprehension would have kept the last one without a word.

`==` on two objects asks whether they're the same object, and an `Integer` is an object. The specification promises that boxing the same small number gives the same object, for "an integer in the range -128 to 127 inclusive", "it is always the case that a == b", and `Integer.valueOf` "will always cache values in the range -128 to 127, inclusive". So in the assistant's test, with two questions a page, both counts were the cached object for 2. On a busy day each count of 200 was an object of its own, and `==` matched only the one `Collections.max` returned. `equals`, or comparing `int`s, compares the numbers.

A `HashMap` stores the key object it's given and finds it again by its hash code and `equals`. The map's docs: "great care must be exercised if mutable objects are used as map keys. The behavior of a map is not specified if the value of an object is changed in a manner that affects equals comparisons while the object is a key in the map." `byHourAndService` cleared and refilled one list for every question, so every entry's key was that list, and after the loop each showed the last question's hour and service: `{[10, SSA]=2, [10, SSA]=1}`. `List.of(...)` makes a new list that can't change, as a Python tuple is. In code you'd keep, a record such as `Slot(int hour, Service service)` is the clearer key, with `equals` and `hashCode` from its parts.
