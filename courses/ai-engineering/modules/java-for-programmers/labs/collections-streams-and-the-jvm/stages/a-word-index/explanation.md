Java's regular expressions are ASCII unless they're told otherwise. Python's `\w`, in a pattern on text, "matches Unicode word characters; this includes all Unicode alphanumeric characters", while Java's `Pattern` docs give `\w` as "a word character: [a-zA-Z_0-9] if UNICODE_CHARACTER_CLASS is not set." Without the flag, `café` is the word `caf` and a lone `é`, so a caller who wrote to the DMV in French or Spanish would match nothing. `Pattern.UNICODE_CHARACTER_CLASS` makes `\w` a word character in any script, as Python's is.

Lowercasing depends on the computer's language unless it's told not to. `String.toLowerCase()` uses the default locale, and its docs give the case that breaks: "For instance, "TITLE".toLowerCase() in a Turkish locale returns "tıtle", where 'ı' is the LATIN SMALL LETTER DOTLESS I character. To obtain correct results for locale insensitive strings, use toLowerCase(Locale.ROOT)." An index built on a server set to Turkish would hold `tıtle`, and a query typed `title` would never find it. Python's `str.lower()` has no locale, so the Python desk never met this.

The index is a map from each word to a set of ids, which Python would write as `defaultdict(set)`. `computeIfAbsent` is that default: it makes the set the first time a word comes up, and gives the set that's there every time after. A `TreeSet` keeps the ids sorted, which is the order `passagesWith` promises. `Collections.unmodifiableSortedSet` returns "an unmodifiable view of the specified sorted set": reads "read through" to the index's own set, and any attempt to change it results "in an UnsupportedOperationException", so a caller can read a word's passages without copying them and can't change the index through them.

`find` counts with `Map.merge`, Python's `counts[id] = counts.get(id, 0) + 1` in one call: "If the specified key is not already associated with a value or is associated with null, associates it with the given non-null value. Otherwise, replaces the associated value with the results of the given remapping function". The query's words go through a `LinkedHashSet` first, so a query that says `card` three times counts it once. The ranking is the comparator chain from the reports: most shared first, then the id.
