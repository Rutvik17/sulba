A `LinkedHashMap` is a hash map that also keeps its entries in a list, and Java builds the least-recently-used cache in from the start. Its docs: "A special constructor is provided to create a linked hash map whose encounter order is the order in which its entries were last accessed, from least-recently accessed to most-recently (access-order). This kind of map is well-suited to building LRU caches." In that order, a `get` or a `put` moves its entry to the end, and the entry at the front is the one used least lately. Python's `OrderedDict` with `move_to_end` is the same structure, done by hand.

The map lets a subclass decide when to forget. `removeEldestEntry` "is invoked by put and putAll after inserting a new entry into the map", and "this is useful if the map represents a cache: it allows the map to reduce memory consumption by deleting stale entries." The docs' own example is the cache here: `return size() > MAX_ENTRIES;`. The method is `protected`, so only a subclass can answer it, and an anonymous class, `new LinkedHashMap<>(...) { ... }`, is a subclass defined where it's used, as a lambda is a function defined where it's used. It sees the cache's fields as `Recent.this.capacity`.

`Recent<K, V>` is a generic class, like Python's `class Recent(Generic[K, V])`, except that Java checks its types when it compiles: a `Recent<UUID, List<String>>` takes only `UUID` keys and lists of strings. `get` returns an `Optional` because a cache that doesn't hold a key has nothing to give, and the cache refuses `null` because a `LinkedHashMap.get` that returns `null` can't say whether the key was missing or held `null`.

The memory a cache saves is the JVM's heap. The JVM gives each program a heap of a fixed most: unless `-Xmx` "specifies the maximum size (in bytes) of the heap", the default is a "maximum heap size of 1/4 of physical memory." The garbage collector "automatically manages the application's dynamic memory allocation requests", and it frees an object only when "it can no longer be reached from any reference of any other live object in the running program." A map is a live object that reaches everything in it, so a cache that never forgets keeps every conversation's agent alive, and the heap fills until the JVM throws an `OutOfMemoryError`, "thrown when the Java Virtual Machine cannot allocate an object because it is out of memory, and no more memory could be made available by the garbage collector." Garbage collection frees what nothing reaches; it can't free what a program still holds, so a bound on what the program holds is the program's job.
