A service reads its settings from its environment, so the same build runs on a laptop and behind the office's load balancer, and a setting that doesn't fit should stop it before it takes a call. Naming every variable that's wrong at once, not only the first, saves whoever deploys it a round trip for each mistake. `Integer.parseInt` refuses what isn't a whole number, `1.5` and an empty string among them, by throwing `NumberFormatException`, so each variable is checked in its own `try`, and the message is built once they all have been.

`HttpServer.stop` takes the grace in seconds, and its docs say what it does with it: it "Stops this server by closing the listening socket and disallowing any new exchanges from being processed. The method will then block until all current exchange handlers have completed or else when approximately delay seconds have elapsed (whichever happens sooner). Then, all open TCP connections are closed". A deploy stops the old service as the new one starts, so with `stop(0)`, every caller whose reply was being written would lose the rest of it in every deploy.

The grace has an end, but the handlers don't stop with it: `stop` closes the connections and returns, and a reply that would take a minute goes on, writing to a closed connection, holding its place at the gate and its model's time. The handlers run on the executor `Server.start` set, which `getExecutor()` gives back, and its `shutdownNow()` "Attempts to stop all actively executing tasks". Its docs say how: "typical implementations will cancel via Thread.interrupt(), so any task that fails to respond to interrupts may never terminate." Your reply's `next` waits in a way an interrupt ends, and your handler closes the reply and gives its place back on the way out. `shutdownNow` "does not wait for actively executing tasks to terminate. Use awaitTermination to do that", so `stop` waits, with a limit of its own, and returns once the service has truly stopped. `close()` would wait too, but it "Initiates an orderly shutdown in which previously submitted tasks are executed", which for a reply of a minute is a minute.
