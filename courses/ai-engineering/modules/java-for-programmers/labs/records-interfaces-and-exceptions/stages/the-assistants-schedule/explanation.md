Each problem passed the assistant's tests because each test used the schedule as the assistant pictured it. Every id was a literal in the test's own code, no day had two bookings, no caller changed a list it was given, and every test opened one day, or two that came out in the right order.

`==` on two strings compares references, as `is` does in Python. The specification: "At run time, the result of == is true if the operand values are both null or both refer to the same object or array", and "the result is false if the operands are distinct String objects, even if they contain the same sequence of characters." The assistant's tests passed because of interning: "a string literal always refers to the same instance of class String", since literals, and strings that are the values of constant expressions, "are 'interned' so as to share unique instances". `"T-2041"` in the test and `"T-2041"` in the schedule were one object. An id that Jackson reads from a request, or that code builds with `+` from a number it reads, is a new object with the same text, and `==` says it's a different id. `equals` compares the text, and it's what Java code uses to compare any two objects by value.

`List<Integer>` has `remove(int index)`, which "removes the element at the specified position in this list", and `remove(Object o)`, which removes an element equal to `o`. `slots.remove(slot)` with an `int` matches the first exactly, and Java picks it before it considers boxing the `int` into an `Integer`: "The first phase performs overload resolution without permitting boxing or unboxing conversion". With every slot free, each slot's number is its place in the list, so the first booking of a day removed the right one. After it, every slot past the booked one sat one place earlier, and the next booking removed its neighbour. `Integer.valueOf(slot)` passes an object, so Java calls `remove(Object)`. A list of numbers that are also places in a list is where this happens, and Python, whose `list.remove` takes only a value, has no such pair.

`bookings()` handed out the schedule's own list, and a caller that sorted its copy for a report sorted the schedule. `List.copyOf` gives a list no one can change, as the desk's methods do.

A `HashMap` keeps its keys in the order their hash codes place them in, and its docs make no promise beyond that: it "makes no guarantees as to the order of the map; in particular, it does not guarantee that the order will remain constant over time." For this week, the days' hash codes put them in reverse. Sorting the keys gives them in the calendar's order, and so would a `TreeMap`, which "is sorted according to the natural ordering of its keys", as the desk's free times were. Python's `dict` keeps the order its keys were added in, and in Java, a `LinkedHashMap` is the map that does.
