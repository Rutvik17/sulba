`ROLLUP ( e1, e2, e3, ... )` "represents the given list of expressions and all prefixes of the list including the empty list", so `ROLLUP (borough, payment)` groups by both, by the borough alone and by nothing, in one pass over the trips. A sublist in parentheses, such as `(payment, name)`, is "treated as single units for the purposes of generating the individual grouping sets", so the payment's code and its name roll up together.

In a subtotal's row, "references to the grouping columns or expressions are replaced by null values", which is also what the trips from a zone with no borough have in `borough`. Testing for `NULL` can't tell a borough's subtotal from the day's total when the borough is the one with no name. `GROUPING` can: it "returns a bit mask indicating which GROUP BY expressions are not included in the current grouping set", with the rightmost argument as the lowest bit, so `GROUPING(borough, payment)` is 0, 1 or 3. Ordering by it as well keeps each subtotal after its payments, whatever the names sort as.

A `numeric` column keeps the exact cents a rider paid, and its `sum` is exact too, where a sum of floats can be off in the last cent. psycopg returns it as Python's `Decimal`, which keeps it exact.
