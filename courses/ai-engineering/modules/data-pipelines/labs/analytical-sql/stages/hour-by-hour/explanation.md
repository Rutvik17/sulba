A count by hour has no row for an hour without a trip, so the series of hours comes first: `generate_series` "generates a series of values from start to stop, with a step size of step", one timestamp for each hour. A `LEFT JOIN` keeps every hour, and an hour that matched no count gets `NULL`, which `coalesce` makes 0. Filtering the trips belongs before that join, in the counting query or in the join's `ON`: Postgres's documentation notes that "a restriction placed in the ON clause is processed before the join, while a restriction placed in the WHERE clause is processed after the join", and a `WHERE` on the trips' columns after a `LEFT JOIN` drops every hour that had none.

A window function works over a frame of rows around the current one. "The default framing option is RANGE UNBOUNDED PRECEDING, which is the same as RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW", so `sum(trips) OVER (ORDER BY hour)` is the running total, and `avg` over the same frame would be the mean of every hour so far. `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` counts rows, three at most, and fewer at the start of the day. `lag` gives the value `offset` rows back, and "if omitted, offset defaults to 1 and default to NULL", so the first hour's change is `NULL`.

`sum(bigint)` and `avg(bigint)` both return `numeric` in Postgres, exact where a float would round, and psycopg returns `numeric` as `Decimal`. For a count and a mean meant as `int` and `float`, the casts go in the query.
