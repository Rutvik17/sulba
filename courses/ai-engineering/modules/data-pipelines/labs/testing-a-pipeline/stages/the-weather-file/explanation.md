GHCN-Daily's readme gives each element's unit: "PRCP = Precipitation (tenths of mm)", "TMAX = Maximum temperature (tenths of degrees C)" and "AWND = Average daily wind speed (tenths of meters per second)". Storing tenths as whole numbers keeps one decimal place without a decimal point, so every value has to be divided by 10 before it means anything.

The flags come from the same readme. A measurement flag "T = trace of precipitation, snowfall, or snow depth", which is why a trace day's rain is 0 rather than missing: rain fell, too little to measure. The quality flag reads "Blank = did not fail any quality assurance check", and each letter names a check that failed, so a value with any quality flag is one the station's record can't vouch for, and `measured` leaves it missing. NCEI's data service documents its attributes as "typically comma separated (e.g., “ T,,0,0700 ”)": the measurement flag first and the quality flag second, which is why `attribute` takes a position.

Spark reads a CSV file's values as strings: its `inferSchema` option, off by default, "Infers the input schema automatically from data. It requires one extra pass over the data." Leaving it off and casting each column keeps the types in the code, where a test can see them. The padded values are why `trim` comes before the cast. `split` takes "a Java regular expression" for its pattern, and a comma is a plain one. An empty field, as in a weather type's column on a day it wasn't seen, comes back missing, so `coalesce` makes it false.
