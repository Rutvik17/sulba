Small counts swing further: EWR had {% $fig.ewr_wednesday_trips %} pickups on {% $fig.manhattan_wednesday %} against {% $fig.ewr_dry_wednesday_trips %} on the dry Wednesday, a change of {% $fig.ewr_wednesday_change %}. That is why each row keeps `dry_days` and `dry_trips` beside its change: what the change was worked out from.

`count_if` "Returns the number of TRUE values for the col", so a day whose `wet` is missing counts as neither wet nor dry. `when` gives the trips only on the days it picks, since "If pyspark.sql.Column.otherwise() is not invoked, None is returned for unmatched conditions", and "NULL values are ignored from processing by all the aggregate functions", so `avg` averages those days alone. Spark's window notes say that "When ordering is not defined, an unbounded window frame (rowFrame, unboundedPreceding, unboundedFollowing) is used by default": with no `orderBy`, each row sees every day of its borough and weekday.
