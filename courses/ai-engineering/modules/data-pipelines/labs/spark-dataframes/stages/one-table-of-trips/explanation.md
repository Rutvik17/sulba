Spark's `union` lines up two DataFrames' columns by where they come: its documentation says "The method resolves columns by position (not by name), following the standard behavior in SQL." `unionByName` instead "performs a union operation on both input DataFrames, resolving columns by name (rather than position)". Here each `select` puts the columns in the table's order, so either would do today, but `unionByName` stays right when a later change gives one side another order.

"PySpark DataFrames are lazily evaluated", in PySpark's own words: "When Spark transforms data, it does not immediately compute the transformation but plans how to compute later. When actions such as collect() are explicitly called, the computation starts." So `trips(spark)` returns at once with a plan, and the trips are read when a test asks for rows, with `count()` or `collect()`.

The files' times have no time zone, and Spark reads them as `timestamp_ntz`: its Parquet settings say timestamp columns "with annotation isAdjustedToUTC = false are inferred as TIMESTAMP_NTZ type". A cast keeps a missing value missing, so the {% $fig.yellow_unreported %} yellow trips that report no passengers have a null `passengers`, not 0.
