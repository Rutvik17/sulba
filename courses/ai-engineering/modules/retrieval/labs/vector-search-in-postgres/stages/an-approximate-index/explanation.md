HNSW puts every vector in the lowest layer of a graph, and some in the layers above, fewer in each, chosen at random as each one goes in. pgvector links each vector to its nearest, at most `m` of them in each layer and twice that in the lowest, found by a search that keeps a list of `ef_construction` candidates. A search starts at the top layer and goes down toward the question, then searches the lowest layer with a list of `ef_search` candidates and returns the nearest of them. pgvector's defaults are {% $fig.m %} for `m`, {% $fig.ef_construction %} for `ef_construction` and {% $fig.ef_search %} for `ef_search`. A larger `ef_construction` finds more of the exact search's passages for a slower build, and a larger `ef_search` does for a slower search.

The layers are drawn at random, so two builds of the same index can find slightly different passages, and the tests compare your index's results with the exact search's over many questions.

An index serves one distance: `vector_cosine_ops` builds it for `<=>`, and pgvector has `vector_l2_ops` for `<->` and `vector_ip_ops` for `<#>`. The planner can use it only for a query that orders by that operator, nearest first, with a `LIMIT`; an expression of the distance, such as `1 - (embedding <=> %s)`, can't use it.

A setting made with `SET` lasts until the connection ends, so one search's `ef_search` would change every search after it on the connection. `SET LOCAL` lasts until its transaction ends, and `set_config(name, value, true)` does the same as a function in a query. psycopg sends parameters apart from a query's text, which `SET` and `CREATE INDEX` don't take, so psycopg's documentation suggests `set_config` for the one, and its `sql` module, which puts values into a statement's text, for the other.

`EXPLAIN` shows the plan Postgres would run a query by, with its estimated cost, without running it: the planner chooses the plan it estimates cheapest. In `FORMAT JSON`, each node of the plan is an object, the nodes under it are in `"Plans"`, and a node that reads an index names it in `"Index Name"`. With no index, the plan reads every row and sorts them by distance.
